# Model Card: Subscription Churn Classifier

## Intended use

Predicts the probability that a telecom-style subscription customer will
churn within the observation window implied by the training data, using
account and usage attributes available at scoring time (tenure, contract
type, billing, support contacts, usage, payment method). Intended as a
**portfolio / reference implementation** of a churn-prediction pipeline --
demonstrating data generation, feature engineering, cross-validated model
selection, calibration, and interpretability. It is explicitly **not**
production-ready for any real business, for the reasons in Limitations
below.

In a real deployment, output probabilities would typically feed a
retention-campaign targeting workflow (e.g., ranking customers by churn risk
to prioritize outreach), not an automated decision that affects a customer
directly.

## Training data

**100% synthetic.** Generated by `src/churn/data/synthetic.py` from a
documented, seeded data-generating process (see that module's docstring for
the exact formula). There is no real customer, billing, or usage data
anywhere in this repository. The generator encodes plausible telecom churn
drivers (short tenure, month-to-month contracts, support-ticket volume, low
usage, lack of autopay) plus two deliberately non-linear effects (a
contract-type x support-tickets interaction and a short-tenure "onboarding
cliff") and Gaussian noise, so that model performance numbers are real and
reproducible but describe fit to a synthetic distribution, not real
subscriber behavior.

## Model

Two models are trained and compared on every run (see `README.md` "Key
Results" for the actual numbers from the last recorded run):

- **Baseline**: logistic regression on standardized, one-hot-encoded
  features, trained on oversampled data.
- **Main model**: XGBoost classifier, trained on oversampled data, evaluated
  with stratified 5-fold cross-validation, and calibrated with
  `CalibratedClassifierCV` when calibration measurably reduces the Brier
  score on out-of-fold predictions.

## Evaluation

ROC-AUC, PR-AUC, F1, and a confusion matrix, all computed on a held-out test
set that neither model saw during training or during the calibration /
decision-threshold selection step (see `README.md` for methodology detail).
Calibration is checked via a reliability diagram (`reports/calibration_curve.png`)
and the Brier score. Feature attribution is provided via SHAP
(`reports/shap_summary.png`).

## Limitations

- **Synthetic training data.** No real customer ever appears in this
  dataset. A model trained here has learned the generator's assumed
  relationships, not real subscriber behavior. Before any real-world use,
  this pipeline would need to be retrained on real, governed customer data
  via a proper warehouse connector (see `src/churn/data/connector.py`).
- **No fairness / bias audit.** The synthetic generator does not model
  protected attributes and none are present in the feature set, but a real
  deployment on real customer data would require an explicit fairness audit
  (e.g. disparate impact analysis across age, geography, or other
  legally-relevant groups) before using model output to influence any
  customer-facing action. `is_senior` is used here purely as a synthetic age
  proxy for realism; whether age-correlated features should be used in a
  real churn model at all is a policy decision outside this repo's scope.
- **No temporal drift modeling.** The synthetic generator produces an
  i.i.d. snapshot; there is no time dimension, concept drift, or seasonality
  in this dataset. A real deployment would need monitoring for feature and
  label drift over time and a retraining cadence.
- **No causal claims.** Feature importance (SHAP) describes association
  learned by the model, not causal drivers of churn. Using these outputs to
  justify a specific retention intervention (e.g. "give discounts to
  month-to-month customers") requires separate causal analysis (e.g. an
  uplift model or an A/B test), not just this classifier's feature
  attributions.
- **Single train/test split for final numbers.** Cross-validation is used
  for the main model's reported CV metrics, but the final head-to-head
  comparison against the baseline uses one held-out test split. Results
  will vary somewhat with the random seed; treat point estimates as
  indicative, not exact.

## Ethical considerations

Churn prediction that leads to retention offers can create fairness
concerns if certain groups are systematically over- or under-targeted for
retention incentives. Any real-world use of a model like this should
include: a bias/fairness audit against legally protected classes, a review
of whether the model's outputs are used for anything beyond internal
prioritization (e.g. never for adverse actions like service restriction),
and a clear data-retention and consent policy for the underlying customer
data. None of this auditing has been performed here since there is no real
data or real deployment target.
